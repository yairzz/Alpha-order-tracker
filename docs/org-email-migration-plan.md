# תוכנית: מעבר לעבודה רק דרך המייל הארגוני

> נכתב: 2026-11-26 · מצב: **תוכנית, לא בוצעה.** המצב הנוכחי מתועד ב-[SPEC.md](../SPEC.md).

**השורה התחתונה:** אפשר להגיע למצב בלי שום תלות בחשבון ה-Gmail הפרטי. הצעד המרכזי הוא שהמייל לשגיא יישלח **ישירות מ-Microsoft 365**, בלי הממסר. זה דורש אישור אחד מאיש ה-IT.

## איפה ה-Gmail הפרטי בשימוש היום
| רכיב | תלות ב-Gmail הפרטי |
|---|---|
| פרויקט Firebase | Owner ראשון. חשבון העבודה כבר נוסף כ-Owner שני (2026-11-23) |
| סקריפט המייל השבועי (`automation/weekly-email.gs`) | רץ בחשבון ה-Gmail, ניגש ל-Firestore בהרשאת בעלים, ושולח מה-Gmail |
| הממסר | Gmail ← Outlook ← Power Automate, עם קוד סודי (`RELAY_TOKEN`) |
| סקריפט הניקוי (`automation/gmail-cleanup.gs`) | קיים רק בגלל העותקים שהממסר משאיר ב-Sent של ה-Gmail |

## השלבים

### שלב 1: להעביר את הסקריפט לחשבון העבודה
- ליצור את פרויקט Apps Script מחדש תחת חשבון ה-Google של העבודה (`yairz@alphatau.com`). החשבון הזה כבר Owner ב-Firebase, ולכן הגישה ל-Firestore תעבוד.
- **לא לשלוח ממנו מייל:** מייל שיוצא משרתי Google בשם כתובת `@alphatau.com` עלול להיחשב מזויף ולהיחסם. השליחה עוברת ל-Microsoft (שלב 2).

### שלב 2: שליחה ישירה מ-Microsoft 365 (דורש IT)
שתי דרכים; איש ה-IT בוחר:
- **(מומלץ) Microsoft Graph:** איש ה-IT רושם אפליקציה ב-Entra ID עם הרשאת `Mail.Send`, **ומגביל אותה לתיבה אחת** (של יאיר, או תיבה ייעודית כמו `orders@alphatau.com`). הסקריפט שולח ישירות, בלי ממסר ובלי Power Automate. סוד האפליקציה נשמר רק ב-Script Properties, לא בקוד.
- **(חלופה) Power Automate עם טריגר HTTP:** הסקריפט שולח את הנתונים לכתובת של התהליך, והתהליך שולח מ-Outlook. דורש רישיון **Premium** של Power Automate.

### שלב 3: פירוק המבנה הישן
אחרי שבוע–שבועיים שבהם השליחה החדשה עובדת:
- למחוק את התהליך **AOT weekly relay** ב-Power Automate.
- למחוק את שני הסקריפטים בחשבון ה-Gmail (מייל שבועי וניקוי). הקוד הסודי נעלם איתם.

### שלב 4: הסרת ה-Gmail מ-Firebase
- **קודם** להוסיף Owner **ארגוני נוסף** (למשל איש ה-IT). אחרת חשבון העבודה הוא Owner יחיד – אותו סיכון בחשבון אחר.
- אחר כך להסיר את ה-Gmail הפרטי: Project settings ← Users and permissions.

### שלב 5 (רשות): כניסה לאתר עם חשבון Microsoft (SSO)
- העובדים נכנסים עם החשבון הארגוני במקום שם משתמש וסיסמה נפרדים.
- פותר את סיכון 6 במסמך האבטחה (אין MFA/SSO) ואת בעיית "סיסמה שאבדה".
- דורש רישום אפליקציה נוסף ב-Entra ID על ידי ה-IT.

## סדר חשוב
**לא להסיר את ה-Gmail לפני שהשליחה החדשה עובדת**, אחרת המייל לשגיא מפסיק לצאת.
הסדר: 1 ← 2 ← בדיקה ← 3 ← 4. בכל המעבר הממסר הישן ממשיך לעבוד כגיבוי.

## מה לבקש מאיש ה-IT (פנייה אחת)
1. אישור למדיניות: חשבון Google על כתובת העבודה (כבר נוצר).
2. רישום אפליקציה ב-Entra ID עם `Mail.Send`, מוגבלת לתיבה אחת. או, אם מעדיפים: Premium ל-Power Automate.
3. (רשות, לשלב 5) אפליקציה נוספת לכניסה ל-Firebase עם Microsoft.
4. מי יהיה ה-Owner הארגוני השני של פרויקט Firebase.
